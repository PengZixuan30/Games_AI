# 技能(Skills)

[返回 README](../../README.zh-TW.md)

技能（skills）是寫給 AI 的**標準作業程序**：一份 Markdown 檔案，說明某類任務該按什麼步驟做、有哪些必須遵守的限制。與工具的分工是——**工具給 AI 能力，技能給 AI 規程**。

## 1. 它解決什麼問題

模型本身知道怎麼呼叫 `modify_custom_tools`，但它不知道你的伺服器上「加白名單前必須先確認玩家名拼寫」或「刪除工程前必須確認工程已認領」。這些規則寫在技能檔案裡，AI 在執行相關任務前讀取，就能按你的流程辦事，而不是按它自己的猜測。

關鍵在於**懶載入**：技能正文不會一直佔用上下文，只有被讀取時才進入對話。所以：

- **技能索引**（`skills.json`）裡只放「什麼時候該讀它」的一句話——這部分**始終**在系統提示裡，屬於固定開銷；
- **技能正文**在你或 AI 判斷需要時才讀入，讀完就留在本輪上下文裡。

因此 `description` 寫得好不好，直接決定 AI 會不會在對的時機想起這個技能。

## 2. 內建技能

插件自帶三個技能檔案，AI 在執行對應操作前會自動讀取，你不需要註冊它們：

| 技能檔案 | 內容 |
|---|---|
| `skills_management.md` | 技能檔案的讀取、寫入、修改、刪除流程 |
| `custom_tools_management.md` | 安全地讀取、編輯、追加自訂工具程式碼的流程。其中包含一條強制步驟：**在動手寫程式碼之前**先向使用者確認需求、參數、權限等級與期望回傳值 |
| `mineflayer_bot_guide.md` | 操控 Mineflayer 假人的流程（僅在假人執行時才出現在索引裡） |

這三個檔案是唯讀參考，通常不需要你改動。

## 3. 加入自己的技能

技能檔案放在：

```
config/games_ai/skills/
```

格式為 Markdown（`.md`）。註冊它需要在同目錄的 `skills.json` 中加入一條：

```json
[
    {
        "file": "whitelist.md",
        "description": "新增/刪除/查詢白名單時都應讀取此技能檔案"
    }
]
```

- **`file`** —— 技能檔案名，相對於 `skills` 目錄；
- **`description`** —— 展示給 AI 的一句話，說明**何時**應讀取它。這是全文最重要的一行：它常駐系統提示，是 AI 判斷「要不要讀」的唯一依據。

註冊後，技能名會出現在 AI 的系統提示中，AI 可用 `read_skills` 工具在執行相關任務前讀取全文。

### 怎麼寫 `description`

| 寫法 | 效果 |
|---|---|
| `"白名單相關"` | 太籠統，AI 很難判斷觸發時機 |
| `"新增/刪除/查詢白名單時都應讀取此技能檔案"` | 明確列出**觸發動作**，AI 能在正確時機想起它 |
| `"建立/控制/刪除假人時必須讀取此技能檔案"` | 用「必須」表明這是強制流程，比「建議」更能約束模型 |
| `"全物品大宗分類物品清單"` | 不是「何時讀」而是「這是什麼」——適用於**查詢型**技能，AI 需要該清單時自然會讀 |

一句話原則：**動作型技能寫「何時必須讀」，資料型技能寫「這是什麼」**。

### 技能正文怎麼寫

正文是給模型的操作規程，不是給人看的文件。經驗做法：

- 開頭一句話說清**適用範圍**（「本技能用於…」）；
- 步驟用有序清單，每步只做一件事；
- 把**不可逆操作**單獨列出並要求確認（「刪除前必須複述工程名並要求玩家確認」）；
- 寫明**失敗時怎麼辦**（「若工具回傳權限不足，直接告知玩家所需等級，不要重試」）；
- 提到具體工具時寫**工具名**（`modify_custom_tools`），模型能直接對應上。

> [!TIP]
> 技能不必長。一份 20 行的清晰規程，比 200 行的模糊說明更能約束模型行為。

## 4. 讓 AI 自己維護技能

AI 有三個工具可以操作技能檔案：

| 工具 | 用途 | 權限 |
|---|---|---|
| `write_skills` | 建立或**覆寫**技能檔案，同時登記到索引（`skills`、`summary`、`content`） | 設定權限 |
| `modify_skills` | 以正規表達式替換**精確修改**已有技能（`old_string`、`new_string`，可選 `summary`） | 設定權限 |
| `delete_skills` | 刪除技能檔案並從索引移除 | 設定權限 |

配合內建技能 `skills_management.md`，AI 會先讀後寫；`write_skills` 是覆寫語意，所以修改已有技能時應當用 `modify_skills`——這樣不會因為一次誤寫丟掉整份檔案。

**實際使用方式**就是直接對 AI 說清楚你要什麼，例如：

```
!!ask 幫我寫一個技能：以後凡是玩家要求傳送，你必須先確認目標玩家在線、
      再複述一次座標，得到確認後才執行。檔案名用 tp_safety.md
```

AI 會先讀 `skills_management.md` 了解流程，用 `write_skills` 寫入檔案並把 `description` 登記進索引。之後你在 `skills.json` 裡就能看到它。

## 5. 在自己的 MCDR 插件中註冊技能

插件可以在載入時以程式設計方式注入技能，無需讀寫磁碟檔案：

```python
from games_ai.external_skills_loader import register_skills

def on_load(server, old):
    register_skills(
        file_name="my_skill.md",
        description="執行 XYZ 操作前應讀取此技能檔案",
        content="""## 我的技能

此技能指導 AI 如何……
- 步驟 1：……
- 步驟 2：……
"""
    )
```

- **`file_name`** —— 技能名，AI 用這個名字呼叫 `read_skills`；
- **`description`** —— 與 `skills.json` 中的同名字段作用一致；
- **`content`** —— 技能全文。

以這種方式註冊的技能與 `skills.json` 裡的技能**完全等價**：同樣出現在系統提示的可用技能清單中，同樣可用 `read_skills` 讀取。差別只有一個——它們**只存在於記憶體中**，插件重載後需要重新註冊。

> [!IMPORTANT]
> 若你的插件只註冊技能（不註冊任何工具），在 GamesAI 執行 `!!gamesai reload` 時它不會自動跟隨重載，請使用 `register_self()`；詳見[熱重載](hot-reload.md#熱重載)。

## 6. 技能與工具的關係

| | 工具（tools） | 技能（skills） |
|---|---|---|
| 本質 | 可被呼叫的函式 | 被讀取的說明文件 |
| 何時進入上下文 | 函式**宣告**始終在（含參數與說明），回傳值在呼叫後進入 | 索引始終在，**正文**只在 `read_skills` 後進入 |
| 誰生效 | 決定 AI **能做什麼** | 決定 AI **該怎麼做** |
| 出錯後果 | 呼叫不動、執行失敗 | AI 按自己的理解行事，結果不可預期 |
| 典型內容 | `modify_custom_tools` | 「改動前必須先讀檔案、先向使用者確認」 |

實踐上兩者總是配套：**給能力的工具 + 給規程的技能**。只有工具沒有技能，AI 會用工具但流程不受控；只有技能沒有工具，AI 知道流程卻做不了事。

## 7. 排查

| 現象 | 檢查點 |
|---|---|
| AI 從不讀某個技能 | `skills.json` 裡的 `description` 是否寫清了觸發時機；檔案名是否與磁碟上的 `.md` 完全一致（含大小寫） |
| 玩家用 `/技能名` 選擇技能時提示「未找到技能檔案」 | 比較時用的是索引裡的 `file` 值；確認副檔名 `.md` 與檔案名拼寫 |
| 改了技能正文但 AI 行為沒變 | 技能正文是**每次讀取時**才載入的，改完直接生效；若改的是 `skills.json` 索引，需要 `!!gamesai reload` |
| 懷疑技能沒被讀進上下文 | 開 `!!gamesai debug`，`read_skills` 的呼叫與結果都會在日誌裡；`!!ask context` 也能看到上下文隨之增長 |
